# Scrittura esterna + server OPC UA — piano per domani

> Per Hermes: eseguire task per task, branch → CI verde → merge → tag → deploy.
> Stato oggi: v3.10.0 live; `fix/dynsec-resub` + `feat/tags-polish` in CI.

**Goal:** (A) interruttore "Abilita scrittura" per login esterni MQTT; (B) server OPC UA affiancato al broker, accendibile per org, con browse Org→Sito→Area→Gateway→Tag e scrittura.

**Flusso scrittura esistente (non si tocca):** `sys/write/{org}/...` → core-api risolve il tag (scoped per org, fail-closed) → `cmd/write/{gatewayID}` → il driver esegue. Tutti i driver ascoltano già `cmd/write`, OPC UA driver incluso.

---

## Fase A — scrittura MQTT per login esterni (mattina)

1. **DB:** colonna `can_write BOOL DEFAULT FALSE` su `mqtt_external_clients` (migration in `internal/db/db.go`, ALTER + CREATE TABLE).
2. **Broker:** in `CreateOrgUser`/`SetClientEnabled` concedere/revocare via dynsec `publishClientSend` su `sys/write/{org_id}/#` quando `can_write` cambia. Default: negato.
3. **API:** `POST /organizations/:id/mqtt-clients/:clientId/write {enabled}` (solo global-admin + audit `mqtt.write.toggle`).
4. **UI:** interruttore "Scrittura" nel pannello MQTT di Sistema + badge "Lettura/Scrittura" nella lista; i18n it/en.
5. **Test 100/100:**
   - E2E: login senza flag pubblica su `sys/write/...` → respinto; con flag → il driver riceve su `cmd/write/{gw}`.
   - E2E: org 2 non raggiunge `sys/write/3/#`; revoca → torna respinto.
   - E2E: toggle scrive riga audit.
   - Manuale su VPS: mosquitto_pub con credenziali login esterno, verificare comando eseguito + riga audit.
6. Branch `feat/ext-write` → CI verde → merge → tag v3.11.0 → deploy.

## Fase B — server OPC UA (pomeriggio)

1. **Nuovo servizio `services/opcua-server`** (Go, libreria `gopcua/opcua`): endpoint `opc.tcp://openedge.metiq.tech:4840`, auth username/password = stessi login esterni del broker (verifica contro stesso store).
2. **Address space piatto, solo scalari:** `Objects/Org/{org}/Site/{site}/Area/{area}/Gateway/{gw}/{tagAlias}` con valore live da Redis `tag_shadow`, quality mappata su OPC StatusCode. Browse gerarchico come app.
   **Fuori scope (decisione): niente UDT né istanze** — nessun tipo strutturato, nessun modello a istanze: ogni tag è un nodo scalare (pressione, batteria, stato). Più semplice da usare per le app esterne, niente mapping da mantenere.
3. **Lettura:** subscription OPC UA servita da ombre Redis (stessa sorgente della dashboard).
4. **Scrittura:** nodi scrivibili solo se login ha `can_write` (riuso flag Fase A); la write entra nello stesso flusso `cmd/write/{gw}` — una sola strada verso i driver.
5. **Toggle per org:** env/flag `OPCUA_ENABLED` globale + campo org; spento = porta chiusa, nessun impatto su MQTT.
6. **Test:** client OPC UA (python asyncua) — browse completo, read valore, write con/senza flag, isolamento org. E2E in CI come Fase A.
7. Branch `feat/opcua-server` → CI verde → merge → tag v3.12.0 → deploy (porta 4840 su VPS).
